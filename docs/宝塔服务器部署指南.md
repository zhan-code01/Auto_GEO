> 适用场景:宝塔面板 + 服务器只有公网 IP(无域名) + 空库启动 + 暂不使用 noVNC 远程扫码授权

## 1. 部署架构

```
公网用户
   ↓ http://服务器IP
宝塔 Nginx (80端口反代) ─→ 127.0.0.1:8080  (前端容器, nginx 静态)
                              └── 内部反代 /api → backend:8001
                                             /ws   → backend:8001
                                             /static → backend:8001

Docker 内部网络 autogeo_network:
  ├─ postgres (5432)   PostgreSQL 15,持久化卷
  ├─ backend  (8001)   FastAPI + Playwright + Xvfb(容器内,不暴露)
  └─ frontend (80)     Vue 静态构建 + nginx
```

设计要点(来自项目实际代码):
- [deploy/production/docker-compose.yml](../deploy/production/docker-compose.yml) 中 `FRONTEND_HTTP_BIND=127.0.0.1:8080` / `BACKEND_HTTP_BIND=127.0.0.1:8001`,只监听本机,由宝塔 Nginx 转发
- [frontend/nginx.conf](../frontend/nginx.conf) 已把 `/api`、`/ws`、`/static` 反代到 backend,所以**宝塔只需反代到 8080 一个端口**
- [backend/main.py](../backend/main.py) 与 [backend/config.py](../backend/config.py) 强制要求 PostgreSQL,代码会直接 `raise ValueError` 拒绝 SQLite
- [backend/entrypoint.sh](../backend/entrypoint.sh) 启动时自动执行 `alembic upgrade head`,空库会自动建表
- [backend/Dockerfile](../backend/Dockerfile) `shm_size: 1gb`(Playwright 必需)

## 2. 服务器与宝塔前置准备

### 2.1 服务器配置
- 至少 2核4G,推荐 4核8G(PostgreSQL + Playwright + Chromium 都吃内存)
- 磁盘 40G 起(Chromium 镜像层 + 容器卷 + 日志)
- 操作系统:Ubuntu 22.04 / Debian 12 / CentOS 7+(宝塔支持)

### 2.2 安装宝塔面板
如果还没装:
```bash
# Ubuntu/Debian
wget -O install.sh https://download.bt.cn/install/install-ubuntu_6.0.sh && bash install.sh ed8484bec

# CentOS
yum install -y wget && wget -O install.sh https://download.bt.cn/install/install_6.0.sh && sh install.sh ed8484bec
```

### 2.3 宝塔内安装必要组件
1. 登录宝塔面板
2. 软件商店 → 安装 **Docker 管理器**(搜 "Docker")
3. 软件商店 → 安装 **Nginx**(宝塔默认会装)
4. 安全 → 放行端口 `80`、`443`(临时调试时再放行 `8080`、`6080`)

### 2.4 配置 Docker 镜像加速器(中国服务器必须做!)

> ⚠️ **不配置的话,拉 postgres/python/node/nginx 基础镜像可能几小时都拉不下来,直接卡死部署。**

**方法 A:宝塔面板配置(推荐)**
1. 宝塔左侧 → Docker → 设置(或"镜像加速",不同版本叫法略不同)
2. 填入加速器地址:`https://docker.m.daocloud.io`
3. 保存 → 重启 Docker(面板有重启按钮;没有就终端执行 `systemctl restart docker`)

**方法 B:阿里云专属加速器(更稳定)**
1. 登录阿里云控制台 → 容器镜像服务 → 镜像加速器
2. 会分配一个专属地址,类似 `https://xxxxxx.mirror.aliyuncs.com`
3. 按阿里云给的文档配置 `/etc/docker/daemon.json`
4. `systemctl restart docker`

**验证加速器是否生效:**
```bash
docker info | grep -A 5 "Registry Mirrors"
# 应该能看到你配置的加速器地址
```

### 2.5 生成密钥
在服务器终端执行,生成两个不同的密钥并记录:
```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

## 4. 配置环境变量(.env)

```bash
cd /opt/autogeo/deploy/production
cp .env.example .env
```

编辑 `.env`,**必须修改的项**(参考 [.env.example](../deploy/production/.env.example)):

```ini
# ==================== 端口绑定(保持默认,只让宝塔 Nginx 反代) ====================
FRONTEND_HTTP_BIND=127.0.0.1:8080
BACKEND_HTTP_BIND=127.0.0.1:8001

# ==================== 前端构建参数(IP 访问,走同源 /api,不需跨域) ====================
VITE_API_BASE_URL=/api
VITE_WS_URL=/ws
VITE_STATIC_URL=/static
VITE_ENABLE_MOCK=false
VITE_APP_TITLE=AutoGeo

# ==================== CORS(只有 IP,填服务器 IP) ====================
# 注意:走宝塔 Nginx 同源反代时,前端到 /api 是同源,不需要 CORS。
# 这里填上是给本地调试或直接访问后端端口用的。
CORS_ORIGINS=http://你的服务器IP,http://你的服务器IP:8080
CORS_ALLOW_ORIGIN_REGEX=

# 日志级别
LOG_LEVEL=INFO

# ==================== PostgreSQL(密码改成你自己的) ====================
# 密码只用字母、数字、下划线,避免 DATABASE_URL 特殊字符转义问题
POSTGRES_DB=autogeo
POSTGRES_USER=autogeo
POSTGRES_PASSWORD=AbCd1234EfGh5678IjKl

# DATABASE_URL 格式: postgresql://用户名:密码@主机:端口/数据库名
# 容器内主机名是 postgres(compose 服务名)
DATABASE_URL=postgresql://autogeo:AbCd1234EfGh5678IjKl@postgres:5432/autogeo

# 连接池
DB_POOL_SIZE=10
DB_MAX_OVERFLOW=20
DB_POOL_TIMEOUT=30
DB_POOL_RECYCLE=3600

# 启动时自动执行数据库迁移(空库第一次启动必须为 true)
RUN_DB_MIGRATIONS=true

# ==================== 必须配置的密钥 ====================
# 用 python3 -c "import secrets; print(secrets.token_urlsafe(32))" 生成
AUTO_GEO_ENCRYPTION_KEY=填入你生成的密钥1
JWT_SECRET_KEY=填入你生成的密钥2

# ==================== 集成服务 ====================
# AI 模型(不填则 AI 相关功能不可用,但能启动)
DEEPSEEK_API_KEY=
DEEPSEEK_API_URL=https://api.deepseek.com/v1

# RAGFlow 知识库
# 代码强制要求:即使没真实 key,也必须填一个非空字符串,否则后端启动会 raise ValueError
RAGFLOW_API_KEY=placeholder-must-be-non-empty
RAGFLOW_BASE_URL=
RAGFLOW_EMBEDDING_MODEL=text-embedding-v4@Tongyi-Qianwen

# n8n 自动化(可选)
N8N_WEBHOOK_URL=
N8N_API_KEY=

# 飞书机器人(可选)
FEISHU_APP_ID=
FEISHU_APP_SECRET=
FEISHU_VERIFICATION_TOKEN=
FEISHU_ENCRYPT_KEY=

# ==================== noVNC(本指南不使用,但 entrypoint.sh 仍会启动 Xvfb,不影响) ====================
# 留空即可,只要不暴露 6080 端口公网就访问不到
VNC_PASSWORD=
NOVNC_PORT=6080
```

**踩坑提示**:
- `RAGFLOW_API_KEY` 在 [backend/config.py](../backend/config.py) 第 737 行有 `if not RAGFLOW_API_KEY: raise ValueError`,**必须非空**,否则后端启动失败
- `AUTO_GEO_ENCRYPTION_KEY` 同样代码强制要求(config.py 第 111 行)
- `DATABASE_URL` 必须以 `postgresql://` 或 `postgresql+` 开头,否则拒绝启动(config.py 第 91 行)

## 5. 构建并启动

### 5.1 一键部署
项目自带部署脚本 [deploy/production/deploy.sh](../deploy/production/deploy.sh):

```bash
cd /opt/autogeo/deploy/production
chmod +x deploy.sh update.sh
./deploy.sh
```

脚本会自动:
1. 检查 docker / git 命令
2. 创建 `n8n_network` Docker 网络(给后续 n8n 用,不影响主流程)
3. `docker compose build` 构建前后端镜像(首次约 10-20 分钟,主要是装 Playwright + Chromium)
4. `docker compose up -d` 启动三个服务
5. backend 容器启动时自动跑 `alembic upgrade head` 建表

### 5.2 验证启动状态
```bash
cd /opt/autogeo/deploy/production

# 查看容器状态(三个都应是 Up / healthy)
docker compose --env-file .env -f docker-compose.yml ps

# 实时看后端日志(看到 "Backend starting..." 和 "应用生命周期" 即正常)
docker compose --env-file .env -f docker-compose.yml logs -f backend

# 健康检查
curl http://127.0.0.1:8080/api/health
# 期望返回: {"status":"ok","services":{"database":{"status":"connected",...}}}
```

如果健康检查返回 `database.status = connected`,说明数据库连接正常,部署成功。

### 5.3 常见启动失败排查

| 现象 | 原因 | 解决 |
|---|---|---|
| backend 容器启动即退出,日志 `RAGFLOW_API_KEY environment variable is required` | `.env` 里 RAGFLOW_API_KEY 留空 | 填任意非空字符串 |
| backend 日志 `AUTO_GEO_ENCRYPTION_KEY environment variable is required` | `.env` 里加密密钥留空 | 用 `python3 -c "import secrets; print(secrets.token_urlsafe(32))"` 生成并填入 |
| backend 日志 `Only PostgreSQL DATABASE_URL values are supported` | DATABASE_URL 不是 postgresql:// 开头 | 改成 `postgresql://autogeo:密码@postgres:5432/autogeo` |
| backend 日志 `alembic upgrade head` 失败 | 数据库未就绪或迁移文件冲突 | 检查 postgres 容器是否 healthy;清空卷重来(见下) |
| 前端访问 502 | 前端容器未启动或后端未就绪 | `docker compose ps` 看状态,`logs frontend` 看日志 |

**清空重来**(慎用,会删除所有数据):
```bash
cd /opt/autogeo/deploy/production
docker compose --env-file .env -f docker-compose.yml down -v
./deploy.sh
```

## 6. 配置宝塔 Nginx 反向代理

### 6.1 添加反向代理站点
宝塔面板 → 网站 → 添加站点:
- 域名:填你的**服务器公网 IP**
- 类型:反向代理
- 目标 URL:`http://127.0.0.1:8080`
- 发送域名:`$host`

### 6.2 (推荐)手动优化站点配置
宝塔默认反代配置对 WebSocket 和长连接支持不完整,建议手动覆盖站点配置:

宝塔 → 网站 → 你的站点 → 配置文件,在 `server {` 块内替换为:

```nginx
server {
    listen 80;
    server_name 你的服务器IP;

    # 大文件上传(文章图片、Excel 批量导入)
    client_max_body_size 100m;

    # 长连接(WebSocket / SSE 流式响应需要)
    proxy_read_timeout 7d;
    proxy_send_timeout 7d;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 支持(/ws 端点和 SSE 流式响应)
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_cache_bypass $http_upgrade;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        proxy_pass http://127.0.0.1:8080;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    access_log /www/wwwlogs/autogeo.log;
    error_log /www/wwwlogs/autogeo.error.log;
}
```

保存后宝塔会自动 reload nginx。

### 6.3 验证访问
浏览器打开 `http://你的服务器IP`,应看到 AutoGeo 登录页。
首次访问需要注册管理员账号(后端没有内置管理员,通过 `/api/users/register` 创建第一个用户)。

## 7. 后续维护

### 7.1 代码更新
项目自带更新脚本 [update.sh](../deploy/production/update.sh),会自动 git pull、判断哪些服务需要重建/重启:

```bash
cd /opt/autogeo/deploy/production
./update.sh
```

脚本逻辑(无需手动记忆):
- `deploy/production/docker-compose.yml` 或 `.env.example` 变了 → 全部重建
- `backend/Dockerfile` / `requirements.txt` / `entrypoint.sh` 变了 → 只重建 backend
- `backend/` 其他代码变了 → 只重启 backend(挂载代码,不重建)
- `frontend/` 任意变化 → 重建 frontend

### 7.2 手动操作常用命令
```bash
cd /opt/autogeo/deploy/production

# 查看状态
docker compose --env-file .env -f docker-compose.yml ps

# 看实时日志
docker compose --env-file .env -f docker-compose.yml logs -f
docker compose --env-file .env -f docker-compose.yml logs -f backend
docker compose --env-file .env -f docker-compose.yml logs -f frontend

# 重启某个服务
docker compose --env-file .env -f docker-compose.yml restart backend

# 重新构建并启动(改了 Dockerfile 或 requirements.txt 后)
docker compose --env-file .env -f docker-compose.yml up -d --build

# 停止所有服务(不删数据)
docker compose --env-file .env -f docker-compose.yml down

# 停止并删除所有数据(危险!仅首次部署失败重来时用)
docker compose --env-file .env -f docker-compose.yml down -v
```

### 7.3 数据备份
定期备份 PostgreSQL 卷(可用宝塔的定时任务):

```bash
# 每日备份脚本示例,放到 /opt/autogeo/backup.sh
#!/bin/bash
BACKUP_DIR=/opt/autogeo/backups
mkdir -p $BACKUP_DIR
DATE=$(date +%Y%m%d_%H%M%S)

# 通过 docker exec 调用 pg_dump
docker exec autogeo_postgres pg_dump -U autogeo -d autogeo -F c -f /tmp/autogeo_$DATE.dump
docker cp autogeo_postgres:/tmp/autogeo_$DATE.dump $BACKUP_DIR/
docker exec autogeo_postgres rm /tmp/autogeo_$DATE.dump

# 保留最近 30 天
find $BACKUP_DIR -name "autogeo_*.dump" -mtime +30 -delete
```

宝塔 → 计划任务 → 添加任务,每天凌晨 3 点执行 `bash /opt/autogeo/backup.sh`。

### 7.4 恢复备份
```bash
# 把 dump 文件拷进容器
docker cp /path/to/autogeo_YYYYMMDD.dump autogeo_postgres:/tmp/restore.dump
# 恢复(会覆盖现有数据)
docker exec autogeo_postgres pg_restore -U autogeo -d autogeo -c /tmp/restore.dump
# 清理
docker exec autogeo_postgres rm /tmp/restore.dump
```

## 8. 重要约束(代码层强制,不能违反)

来自 [backend/config.py](../backend/config.py) 和 [backend/main.py](../backend/main.py) 的硬性约束:

| 约束 | 位置 | 后果 |
|---|---|---|
| DATABASE_URL 必须以 `postgresql://` 或 `postgresql+` 开头 | config.py:91 | 启动失败 |
| AUTO_GEO_ENCRYPTION_KEY 必须非空 | config.py:111 | 启动失败 |
| RAGFLOW_API_KEY 必须非空 | config.py:737 | 启动失败 |
| pytest 不允许跑在非 test 库 | config.py:79 | 测试失败 |
| 后端只监听 8001,前端 nginx 容器内反代 /api /ws /static | frontend/nginx.conf | 不能直接访问 backend:8001/api,要走 8080 |

## 9. 后续扩展

### 9.1 将来需要域名 + HTTPS
1. 域名解析到服务器 IP
2. 国内服务器需要先 ICP 备案
3. 宝塔 → 网站 → 你的站点 → SSL → 申请 Let's Encrypt 免费证书
4. 开启强制 HTTPS
5. `.env` 里 `CORS_ORIGINS` 加上 `https://你的域名`

### 9.2 将来需要 noVNC 远程扫码授权
1. `.env` 里设置 `VNC_PASSWORD=一个强密码`
2. 宝塔安全放行 `6080` 端口(或加 nginx 反代 `/novnc/` 到 `127.0.0.1:6080`)
3. 重启 backend: `docker compose --env-file .env -f docker-compose.yml restart backend`
4. 访问 `http://服务器IP:6080/vnc.html`,输入 VNC 密码即可看到浏览器桌面

### 9.3 性能调优(高并发场景)
- 服务器内存够大时,调大 `DB_POOL_SIZE=20`、`DB_MAX_OVERFLOW=50`
- 宝塔 Nginx 开启 gzip(前端 nginx.conf 已开,宝塔层再加一层)
- 后端容器 `shm_size: 1gb` 已设,如多个 Playwright 并发可调到 `2gb`
- PostgreSQL 配置:进容器改 `postgresql.conf` 的 `shared_buffers`、`max_connections`
