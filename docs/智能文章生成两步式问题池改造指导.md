# 智能文章生成两步式问题池改造指导

> 目标读者：负责继续实现该模块的开发者或编码 Agent（Luna）  
> 文档性质：在现有“智能文章生成”第一版上的增量改造依据  
> 最后更新：2026-07-14  
> 优先级：本文档中的最新决策覆盖 `docs/智能文章生成模块实施规划.md` 中“一键生成后立即写文章”的旧流程；未被本文档修改的知识库、文章格式、图片、发布和安全要求继续有效。

---

## 1. 改造目标

当前模块把以下步骤串在一次操作中：

```text
生成候选问题 → 筛选问题 → 立即生成文章
```

本次改为明确的两步式流程：

```text
第一步：生成并筛选问题 → 保存到项目问题池 → 前端展示
第二步：用户复选一个或多个未生成问题 → 批量生成对应文章
```

核心目的不是增加复杂的问题管理系统，而是让用户能够：

1. 先看到 AI 最终筛选出的用户问题；
2. 看出问题是否已经生成文章；
3. 按“是否生成文章”筛选；
4. 通过复选框选择一个或多个问题生成文章；
5. 批量删除问题；
6. 删除问题时不删除已经生成的文章；
7. 被删除问题仍用于以后生成问题时的历史去重。

本次不实现问题编辑、回收站、恢复、质检或复杂的问题状态管理界面。

## 2. 已确认的产品决策

### 2.1 页面输入

页面上方保留：

| 字段 | 规则 |
| --- | --- |
| 项目 | 必填，使用现有项目数据 |
| 生成问题数量 | 自动模式必填，建议 1～50，默认 10 |
| 自定义问题 | 可选；填写后数量锁定为 1 |

原“文章数量”改名为“生成问题数量”。文章数量不再单独输入，最终文章数量等于用户勾选的未生成问题数量。

### 2.2 自动问题

- 自动模式继续使用现有 Prompt 1生成候选问题；
- 继续使用现有 Prompt 2筛选推荐价值高的问题；
- Prompt 1和 Prompt 2仍然不检索知识库；
- 筛选完成后只保存问题，不创建 `GeoArticle`，不创建文章生成任务；
- 新问题追加到当前项目的问题池，不覆盖原问题；
- 所有历史问题，包括软删除问题，都参与后续问题去重。

### 2.3 自定义问题

- 自定义问题不调用 Prompt 1和 Prompt 2；
- 不改写用户输入；
- 直接保存到问题池；
- 默认状态为“未生成文章”；
- 若同项目已经存在标准化文本相同的问题，包括已软删除的问题，返回明确的重复提示，不重复插入。

### 2.4 问题列表

问题列表至少支持：

- 项目内问题分页；
- “全部、未生成文章、已生成文章”筛选；
- 问题复选框；
- 批量生成文章；
- 批量删除问题；
- 显示问题文本、是否生成文章、创建时间；
- 可选显示来源：AI生成或用户输入。

不提供问题编辑按钮。

### 2.5 已生成问题

- 已生成问题默认不能再次生成文章；
- 前端复选框仍允许选中已生成问题，以便与其他问题一起批量删除；
- 批量操作区明确显示“已选择 N 条，可生成 M 条”；
- “生成 M 篇文章”只提交其中未生成且没有活动任务的问题；
- 如果 `M=0`，生成按钮禁用；
- 后端必须再次校验，不可只依赖前端禁用。

### 2.6 删除语义

“删除问题”采用软删除：

```text
is_deleted = true
deleted_at = 当前时间
```

规则：

- 删除后不出现在正常问题列表；
- 删除问题不删除 `GeoArticle`；
- 删除问题不取消已经开始的文章任务；
- 被删除问题仍进入 Prompt 历史排除列表；
- 本次不提供恢复和回收站界面；
- 禁止物理删除后再单独复制到所谓历史表，避免无意义的双表维护。

## 3. 关键词相关表达拓展

### 3.1 是否调用 AI

需要使用 AI。固定词典无法稳定覆盖餐饮、制造、医疗、企业服务等不同项目，也无法可靠处理“智能客服 / 智慧客服 / AI客服”这类自然表达差异。

但本次不新增独立 Prompt，也不额外增加一次模型调用。拓展工作并入现有 Prompt 1：

```text
领域关键词、行业、地域、项目描述
→ 同一次 Prompt 1调用先生成高相关表达
→ 再利用这些表达生成多样化候选问题
```

Prompt 1结构化返回：

```json
{
  "expanded_terms": [
    {"term": "智慧客服", "relation": "synonym"},
    {"term": "AI客服", "relation": "synonym"},
    {"term": "客服机器人", "relation": "adjacent"},
    {"term": "系统接入", "relation": "concern"},
    {"term": "售后咨询", "relation": "scenario"}
  ],
  "questions": [
    {
      "question": "广州有哪些AI客服服务商值得了解？",
      "intent_type": "provider",
      "context_type": "region",
      "related_terms": ["AI客服", "服务商", "广州"],
      "brand_entry_reason": "回答时可以自然介绍目标项目作为候选"
    }
  ]
}
```

`relation` 只允许：

- `synonym`：近义或用户常用表达；
- `adjacent`：高相关相邻主题；
- `scenario`：使用场景；
- `concern`：用户关注点。

### 3.2 拓展边界

- 核心领域关键词不能被替换或丢失；
- 只保留与核心主题高相关的表达；
- 拓展词只用于扩大问题表达范围，不代表目标公司拥有对应功能；
- 不得根据拓展词虚构公司功能、客户、案例、资质、价格、排名、服务范围或效果；
- 问题不能只是把同一句话中的“智能客服”依次替换成“智慧客服、AI客服”；
- Prompt 2仍负责淘汰纯百科、品牌无法自然进入和语义重复的问题；
- `expanded_terms` 可以保存到问题生成批次作为调试信息，不要求单独做前端管理页面。

### 3.3 Prompt 版本

修改后提升版本号，建议：

```text
Prompt 1：smart_question_v2
Prompt 2：smart_question_filter_v2
Prompt 3：沿用当前版本；如同步调整FAQ规则则升级为smart_article_v2
Prompt R：保持当前版本
```

Prompt 2的输入增加本次 `expanded_terms`，但不能把拓展词当作公司事实。

## 4. 数据模型

### 4.1 新增独立问题表

不要继续把“问题池”只存在 `SmartArticleJob` 或 `Keyword` 中。新增 `SmartArticleQuestion`，建议表名：

```text
smart_article_questions
```

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Integer | 主键 |
| user_id | Integer | 数据归属，遵守现有用户隔离 |
| project_id | Integer | 所属项目 |
| generation_batch_id | Integer, nullable | 来源问题生成批次 |
| question | Text | 用户问题原文 |
| normalized_question | String(255) | 去标点、空格并小写后的精确去重值 |
| source | String(20) | `ai` 或 `manual` |
| intent_type | String(30) | provider/selection等 |
| context_type | String(20) | general/industry/region |
| brand_entry_reason | Text, nullable | 公司自然进入理由 |
| retrieval_terms | JSON, nullable | 后续构建知识库Query使用 |
| has_article | Boolean | 是否曾成功生成文章，默认false |
| article_id | Integer, nullable | 最近一次成功文章ID；文章删除时允许置空 |
| article_generation_status | String(20) | 内部状态：idle/generating/failed/generated |
| is_deleted | Boolean | 软删除标记，默认false |
| deleted_at | DateTime, nullable | 删除时间 |
| created_at | DateTime | 创建时间 |
| updated_at | DateTime | 更新时间 |

约束与索引：

- `user_id`、`project_id`、`is_deleted`、`has_article` 建索引；
- `(project_id, normalized_question)` 建唯一约束；
- `article_id` 可关联 `geo_articles.id`，删除文章时 `SET NULL`；
- `has_article` 表示“曾经成功生成过”，文章被删除时不得自动改回false；
- `article_generation_status` 是防并发和失败重试所需的内部字段，前端筛选仍只暴露是否生成文章。

### 4.2 调整现有任务表

在 `SmartArticleJob` 增加：

```text
question_id → smart_article_questions.id
```

任务中继续保留 `question` 文本快照，避免问题记录变化影响历史任务审计。

文章生成幂等键应以问题为核心，不能继续仅依赖批次ID：

```text
smart_article:{user_id}:{project_id}:{question_id}:{article_prompt_version}:{retry_nonce}
```

同一问题存在成功文章或活动任务时，后端拒绝重复创建任务；失败重试可以追加新的批次ID作为重试 nonce，但幂等键的核心必须仍是 `question_id`，不能只使用批次ID。

### 4.3 调整批次表

继续复用 `SmartArticleBatch`，增加：

```text
batch_type = question_generation | article_generation
expanded_terms = JSON, nullable
```

- 问题生成批次只负责 Prompt 1、Prompt 2和保存问题；
- 文章生成批次只负责被选问题的检索、写作、图片和保存；
- 两类批次都立即返回 `batch_id` 并在后台执行；
- 批次详情应返回 `batch_type`。

### 4.4 现有数据回填

迁移后把已有 `SmartArticleJob` 中的问题幂等回填到 `SmartArticleQuestion`：

- 同一项目标准化后相同的问题只保留一条；
- 成功任务对应问题设置 `has_article=true`；
- 复制最近成功的 `article_id`；
- `source` 可记为 `ai`，旧手动批次可根据 `SmartArticleBatch.mode` 识别为 `manual`；
- 将原任务的 `question_id` 回填到新问题记录；
- 数据回填不得删除或改写已有文章和任务。

## 5. 后端流程

### 5.1 生成问题

请求：项目、生成问题数量、可选自定义问题。

自动模式：

1. 校验项目归属和必填资料；
2. 读取该项目全部历史问题，包括 `is_deleted=true`；
3. Prompt 1在同一次调用中生成 `expanded_terms` 和候选问题；
4. Prompt 2结合历史问题筛选；
5. 程序执行标准化文本去重；
6. 保存最终问题到 `SmartArticleQuestion`；
7. 不创建 `Keyword`、`GeoArticle` 或 `SmartArticleJob`；
8. 返回或轮询得到新增问题列表。

自定义模式：

1. 保留原文；
2. 标准化后检查同项目唯一性；
3. 保存一条 `source=manual` 的未生成问题；
4. 跳过 Prompt 1和 Prompt 2。

### 5.2 查询问题池

默认条件：

```text
project_id = 当前项目
is_deleted = false
```

筛选：

- 未生成：`has_article=false`；
- 已生成：`has_article=true`；
- 全部：不增加 `has_article` 条件。

必须使用当前用户数据隔离，不能通过修改 `project_id` 读取其他客户问题。

### 5.3 批量删除问题

输入问题ID数组，逐条校验归属，然后批量设置软删除字段。

- 允许同时删除已生成和未生成问题；
- 不删除文章；
- 不删除任务；
- 不物理删除问题；
- 返回实际删除数量。

### 5.4 根据已选问题生成文章

输入：

```json
{"project_id": 1, "question_ids": [11, 12, 13]}
```

后端必须：

1. 校验所有问题属于当前用户和当前项目；
2. 排除 `is_deleted=true`；
3. 排除 `has_article=true`；
4. 排除 `article_generation_status=generating`；
5. 对可生成问题创建文章批次、任务和 `GeoArticle` 占位记录；
6. 每个任务关联 `question_id`，并保留问题文本快照；
7. 将问题内部状态置为 `generating`；
8. 继续复用现有动态Query、RAGFlow、Prompt 3、格式校验、图片处理和Markdown转HTML；
9. 单篇成功后设置 `has_article=true`、`article_generation_status=generated`、`article_id=文章ID`；
10. 单篇失败后保持 `has_article=false`，设置 `article_generation_status=failed`，允许再次勾选生成；
11. 单篇失败不能影响同批其他问题；
12. 请求立即返回 `batch_id`。

### 5.5 标题、正文和FAQ

继续保持：

- 用户问题与文章标题是两个字段；
- 标题由 Prompt 3根据问题提炼，最多20个汉字；
- 标题不得机械复制过长用户问题；
- 正文入库前移除与标题相同的首个H1，避免预览和发布出现双标题；
- 每篇文章保持2～3个图片占位符；
- 图片保持响应式展示。

FAQ调整为可选：

- 存在真实补充追问时生成2～4个FAQ；
- 不需要FAQ时允许不生成；
- 不得为了固定格式机械添加FAQ；
- FAQ不能重复正文已经完整回答的问题。

## 6. API建议

统一前缀继续使用：

```text
/api/smart-articles
```

### 6.1 问题接口

```text
POST   /question-batches
GET    /question-batches/{batch_id}
GET    /questions
POST   /questions/batch-delete
```

`POST /question-batches`：

```json
{
  "project_id": 1,
  "question_count": 10,
  "custom_question": null
}
```

`GET /questions` 查询参数：

```text
project_id
has_article=true|false（可省略）
page
limit
```

`POST /questions/batch-delete`：

```json
{"question_ids": [11, 12, 13]}
```

### 6.2 文章生成接口

```text
POST /article-batches
GET  /batches/{batch_id}
```

`POST /article-batches`：

```json
{
  "project_id": 1,
  "question_ids": [11, 12, 13]
}
```

响应立即返回：

```json
{
  "success": true,
  "data": {
    "batch_id": 20,
    "accepted_question_ids": [11, 12, 13],
    "skipped_question_ids": []
  }
}
```

现有文章列表、预览、编辑、发布、删除和失败任务重试接口继续保留。

为兼容开发中的旧调用，可以临时保留现有 `POST /generate`，但新页面不得再调用它；确认无其他调用方后再单独废弃，不要在本次直接删除。

## 7. 前端页面

页面仍使用：

```text
frontend/src/views/geo/SmartArticles.vue
```

### 7.1 问题生成区

```text
项目：[请选择项目]
生成问题数量：[10]
自定义问题（可选）：[________________]
                                      [生成问题]
```

- 自定义问题非空时数量自动锁定为1；
- 按钮文案从“一键生成”改为“生成问题”；
- 问题批次执行时显示生成和筛选进度；
- 完成后刷新问题池，不自动生成文章。

### 7.2 问题池

使用可折叠卡片，建议默认展开：

```text
用户问题（12）                                      收起

筛选：[全部] [未生成文章] [已生成文章]       [刷新]

☐ 广州有哪些AI客服服务商值得了解？       未生成文章
☐ 制造企业选择智能客服要注意什么？       未生成文章
☐ 智能客服如何对接CRM？                  已生成文章

已选择 3 条，可生成 2 条       [生成2篇文章] [删除3个问题]
```

交互规则：

- 所有可见问题都允许勾选，以支持混合批量删除；
- “生成文章”按钮只统计未生成且无活动任务的问题；
- 已生成问题不会被提交生成；
- 生成前确认框显示将生成数量和被忽略的已生成数量；
- 批量删除确认框明确说明“删除问题不会删除已经生成的文章”；
- 删除成功后刷新问题池，文章列表不变化；
- 不显示问题编辑入口。

### 7.3 文章区

保留当前智能文章列表：

- 只显示 `source=smart_article`；
- 保留项目、状态筛选；
- 保留预览、编辑、去发布、文章删除和刷新；
- 不显示质检；
- 文章生成批次继续展示完成、失败和处理中数量。

## 9. 状态与并发规则

### 9.1 问题生成批次

```text
pending → planning_questions → filtering_questions → saving_questions → completed
                                                               ↘ failed
```

### 9.2 文章生成批次

继续使用现有状态流转。问题行的内部状态同步为：

```text
idle → generating → generated
                 ↘ failed
```

### 9.3 并发和幂等

- 批量文章继续有限并发，默认3；
- 选中问题提交时必须在事务中锁定或原子更新问题状态；
- 两个请求不能同时为同一问题创建两篇文章；
- 成功文章存在时拒绝重复生成；
- 失败问题允许重新生成；
- 重试复用原文章占位记录或保证幂等，不能重复保存成功文章。

## 10. 实施顺序

1. 检查当前分支和工作树，保留现有未提交改动；
2. 新增迁移、`SmartArticleQuestion` 模型和现有数据回填；
3. 给 `SmartArticleBatch`、`SmartArticleJob` 增加所需字段；
4. 改造 Prompt 1，使一次AI调用返回拓展词和候选问题；
5. 实现问题生成批次、问题池保存、列表和软删除；
6. 将文章生成入口改为接收 `question_ids`；
7. 文章成功或失败后同步问题标记；
8. 改造前端为“问题生成区 + 问题池 + 文章列表”；
9. 保留现有文章预览、图片尺寸、双标题修复、编辑和发布能力；
10. 增加测试并回归旧模块。

## 11. 必测场景

### 11.1 问题生成

- “智能客服”能够得到“智慧客服、AI客服”等高相关表达；
- 拓展词与候选问题由同一次 Prompt 1调用返回；
- Prompt 2仍会筛掉无推荐价值和语义重复问题；
- 自动模式只保存问题，不创建文章；
- 自定义问题跳过 Prompt 1和 Prompt 2；
- 自定义问题数量锁定为1；
- 同项目标准化重复问题不能再次插入；
- 不同项目允许存在相同问题；
- 已删除问题仍进入历史排除列表。

### 11.2 问题列表

- 默认不显示软删除问题；
- 可以筛选全部、已生成、未生成；
- 可以混合勾选已生成和未生成问题；
- 生成按钮只统计可生成问题；
- 批量删除同时支持已生成和未生成问题；
- 删除问题不删除文章；
- 页面没有问题编辑按钮。

### 11.3 批量文章

- 勾选1个未生成问题创建1篇；
- 勾选5个未生成问题创建5篇；
- 已生成问题不会重复创建文章；
- 两个并发请求不能为同一问题重复建任务；
- 单篇失败不影响其他问题；
- 成功后问题标记为已生成；
- 失败后仍为未生成并允许重试；
- 最终文章继续为 `source=smart_article` 和草稿；
- 文章继续进入当前文章管理和发布流程。

### 11.4 文章格式

- 标题不超过20个汉字；
- 标题与用户问题分别保存；
- 正文和标题不重复显示；
- FAQ可以存在，也可以不存在；
- 图片保持2～3张且预览不横向溢出；
- 无知识库仍能降级生成通用文章。

### 11.5 回归

- 旧“GEO文章生成”页面、接口和Prompt不变；
- 文章管理可看到智能文章；
- 智能文章预览、编辑、删除文章和去发布可用；
- 前后端用户隔离正确；
- 迁移升级、回滚和旧数据回填可验证。

## 12. 验收标准

满足以下流程即为通过：

```text
选择项目并输入问题数量
→ AI拓展相关表达、生成候选并筛选
→ 前端看到最终问题
→ 按是否生成文章筛选
→ 混合选择问题
→ 对未生成问题批量生成文章
→ 成功问题显示已生成
→ 软删除问题后不再显示，但不会再次被AI生成
→ 已有文章不受问题删除影响
```

最终实现必须保持产品界面简单：用户看到的核心只有“生成问题、选择问题、生成文章、删除问题、是否已生成文章”。内部批次、状态、幂等和软删除细节不应增加额外操作负担。
