## 四、遇到的卡点及解决方案

### 卡点 1: Docker 镜像拉取慢
**现象**: 拉 postgres、python、node、nginx 镜像卡死
**原因**: 中国服务器访问 Docker Hub 慢
**解决**: 配置 Docker 镜像加速器 `https://docker.m.daocloud.io`

### 卡点 2: apt-get install 慢
**现象**: 后端构建时 `apt-get install` 耗时 30+ 分钟
**原因**: 容器内走 Debian 官方源 `deb.debian.org`，国内慢
**解决**: Dockerfile 里加 `echo "deb http://mirrors.aliyun.com/debian trixie main" > /etc/apt/sources.list`

### 卡点 3: .env 被覆盖
**现象**: 每次重新解压源码包，.env 被覆盖回占位符
**原因**: 源码包里包含 .env（从本地带来的）
**解决**: 
1. 服务器上备份 .env 到 `/opt/.env.backup`
2. 每次解压后从备份恢复：`cp /opt/.env.backup /opt/Auto_GEO-main/deploy/production/.env`

### 卡点 4: entrypoint.sh exec format error
**现象**: 容器启动报 `exec /app/entrypoint.sh: exec format error`
**原因**: Windows 换行符（CRLF）和 BOM 头
**解决**: Dockerfile 里加 `sed -i 's/\r$//'` 和 `sed -i '1s/^\xEF\xBB\xBF//'`

### 卡点 5: entrypoint.sh 语法错误
**现象**: `syntax error near unexpected token 'else'`
**原因**: 第 77 行注释和 sed 命令在同一行，`#` 把 sed 也注释了，导致 if 块没有执行体
**解决**: 分离注释和命令为两行

### 卡点 6: noVNC 权限问题
**现象**: `sed: couldn't open temporary file /usr/share/novnc/sedUyFXcx: Permission denied`
**原因**: entrypoint.sh 以 autogeo 用户运行，无法写 `/usr/share/novnc/`（root 的目录）
**解决**: 把 noVNC CSS 注入移到 Dockerfile，以 root 身份在构建时执行

### 卡点 7: Xvfb 锁文件导致崩溃循环
**现象**: 容器反复崩溃重启，日志显示 `Server is already active for display 99`
**原因**: 上次崩溃留下的 `/tmp/.X99-lock` 没清理，Xvfb 认为 display 99 已被占用
**解决**: entrypoint.sh 启动 Xvfb 前加 `rm -f /tmp/.X${DISPLAY_NUMBER}-lock`

### 卡点 8: 卷挂载覆盖容器内文件
**现象**: 即使 Dockerfile 里生成了干净的 entrypoint.sh，容器里还是旧文件
**原因**: docker-compose.yml 里 `../../backend:/app/backend` 卷挂载把宿主机文件覆盖到容器
**解决**: 注释掉这行 `# - ../../backend:/app/backend`

### 卡点 9: 打包路径问题
**现象**: 解压后文件散在 `/opt/` 下，没有 `Auto_GEO-main` 目录
**原因**: 打包时用了 `tar -czf ... .`（从目录内部打包），而不是 `tar -czf ... Auto_GEO-main`
**解决**: 
- 方案 A: 打包时用 `tar -czf autogeo-src.tar.gz -C d:\GEO Auto_GEO-main`
- 方案 B: 解压后手动整理：`mkdir Auto_GEO-main && tar xzf autogeo-src.tar.gz -C Auto_GEO-main`

### 卡点 10: alembic_version 字段长度不足（当前卡点）
**现象**: 后端崩溃，日志显示 `value too long for type character varying(32)`
**原因**: 
- 数据库是空库，alembic 自动创建 `alembic_version` 表时用了默认 `varchar(32)`
- 迁移版本号如 `0006_add_project_members_and_task_attribution` 有 47 字符，装不下
- 备份 SQL 显示原来用的是 `varchar(128)`
**解决**: 手动修改字段长度：
```sql
ALTER TABLE alembic_version ALTER COLUMN version_num TYPE varchar(255);
```
**注意**: 这个表是 alembic 自动创建的，需要先启动一次后端让它创建表，然后修改字段，再重新启动。

### 卡点 11: 8080 端口被占用
**现象**: `curl http://127.0.0.1:8080/api/health` 返回 blueblood 的数据
**原因**: blueblood 项目占用了 8080 端口
**解决**: 修改 docker-compose.yml，将前端端口从 8080 改为 8082
